# 防合盖休眠 · 让 MacBook 合上盖子后继续运行

一句话：**合上盖子后，系统不休眠、Wi‑Fi 不断、Tailscale 不离线、RustDesk / ToDesk 远程桌面随时能连进来，而且远程看到的是真实画面（不是黑屏）。**

实现上分两层：
1. **系统级**：`pmset disablesleep 1` 关掉「合盖休眠」，再加一个守护进程防止开关被第三方软件改回去；
2. **画面级**：合盖时自动创建一个 2 倍像素的虚拟显示器、并把内建屏背光调到 0 —— 屏幕物理上不亮，但系统仍在渲染，远程桌面抓到的是虚拟屏的真实画面；开盖后自动恢复。

适用机型：本机 MacBook Air（Apple M4 / macOS 15.7.9），原理对 Intel Mac 同样适用。

## 原理（为什么这样就够了）

macOS 的合盖休眠由系统电源管理里的一个开关控制：`pmset disablesleep`。

```
sudo pmset -a disablesleep 1     # 关闭「合盖休眠」
sudo pmset -a disablesleep 0     # 恢复「合盖休眠」
```

打开后，系统不再因为「合盖」进入睡眠。网络接口、Tailscale 后台进程、RustDesk / ToDesk 服务都还在运行，
所以从外网通过 Tailscale IP（本机 `100.91.137.116`）就能连回远程桌面。

这个设置写在 `/Library/Preferences/com.apple.PowerManagement.plist` 里，**重启、关机后仍然有效**。

**为什么不用 `caffeinate`？**
`caffeinate` 只能阻止「闲置休眠」（idle sleep），管不住「合盖休眠」（clamshell sleep）这条路径，合盖后系统照样睡。

**为什么必须要管理员密码？**
这是系统级电源策略，普通用户没有权限修改，所以脚本会调用 macOS 官方的授权弹窗（`osascript ... with administrator privileges`）。
密码只会交给系统弹窗，脚本里没有任何保存密码的逻辑。

### 画面层：为什么合盖后远程还能看到画面

只开 `disablesleep` 会带来两个新问题，也是本项目后半段解决的：

| 问题 | 原因 | 解法 |
| --- | --- | --- |
| 合盖后内建屏**一直亮着** | macOS 的「合盖关屏」是跟着「合盖休眠」一起发生的；不让它睡，它就不关屏 | 合盖时把内建屏**背光调到 0**（`DisplayServicesSetBrightness`），屏幕物理不亮，但渲染继续 |
| 合盖后远程桌面**全黑** | 内建屏是唯一显示器，合盖后 WindowServer 不再为它合成画面 | 合盖时**创建一个 HiDPI 虚拟显示器**（`CGVirtualDisplay` 私有 API，逻辑 1470×956 / 物理 2940×1912），系统有第二个可渲染的屏，远程抓到的就是真实画面 |

这两件事由用户级守护进程 `com.yyz.lidawake`（`.lidwatch.sh`）在合盖/开盖时自动完成，每 1 秒检查一次盖子状态，开盖即恢复亮度并销毁虚拟屏。
虚拟屏**只在合盖时存在**：如果一直挂着，RustDesk 会在两块屏之间反复切换，导致远程画面模糊甚至卡死（这是实测踩过的坑）。

## 注意事项

- **耗电**：合盖后系统还在跑，电池供电时大约每小时掉 5%～10%（取决于负载）；插着电就没感觉。
- **发热**：不要把正在合盖运行的 Mac 塞进包里/抽屉里，散热口被堵会明显发热降频。
- **电池健康**：macOS 的充电管理不受影响，无需额外设置。
- **系统升级后**：macOS 大版本升级有可能重置电源策略，升级完运行一次 `3-查看状态.command` 复查即可。
- **想临时恢复休眠**：双击 `2-关闭防合盖休眠.command`；**关机并不会关闭它**，必须运行 2 号脚本。
- **公司电脑**：本机未受 MDM 管理（已确认），改动本地电源策略是纯本机行为。

## 关于「合盖后远程桌面看到黑屏」

合盖后 macOS 会关掉内建屏；如果没有任何别的显示器，WindowServer 就不再合成画面，远程桌面抓到的是纯黑。
本方案用「合盖时创建 HiDPI 虚拟显示器 + 内建屏背光归零」解决了它，所以正常情况下**不需要额外硬件**。

如果还是黑屏，按顺序排查：

1. **先确认画面守护在跑**：运行 `3-查看状态.command`，看「画面守护」是否 ✅ 运行中、合盖时「虚拟屏」是否显示已创建。
   如果显示未运行：重跑 `1-开启防合盖休眠.command`。
2. **看测试报告里的「四、画面」**：`4-合盖测试.command` 会在合盖期间截屏，正常桌面截图是 MB 级别，
   如果都只有 100 KB 左右，说明画面确实是黑的。
3. **看画面守护日志**：`~/Library/Application Support/yz-keepawake/logs/合盖画面守护.log`，
   正常会看到「检测到合盖 → 创建虚拟屏 → 背光归零」和开盖时的「恢复亮度 / 移除虚拟屏」。
4. **换一个远程桌面软件试试**：本机同时装了 RustDesk 和 ToDesk，抓屏实现不同（此前 RustDesk 在多显示器切换时曾卡死，重启它的后台服务即可）。
5. **兜底硬件方案**：接一个 HDMI / USB‑C「诱骗器」（dummy plug，几十元），系统会认为接了外接显示器，效果类似。

> 说明：脚本已经把能自动验证的都验证了，但「远程客户端里看到的画面」仍需你实际连一次确认。

## 常见问题

**Q：开机密码会被保存吗？**
不会。密码只输入到 macOS 系统自带的授权弹窗里，脚本只负责调用 `/usr/bin/pmset`。

**Q：能不能只在插电的时候生效？**
`disablesleep` 是全局开关，不区分电源。如果希望「插电才不休眠」，可以拔电前运行 `2-关闭防合盖休眠.command`。

**Q：合盖后会不会自动锁屏？**
会。macOS 默认要求密码解锁，这是**正常且安全**的：远程桌面连上去看到的是锁屏/登录界面，解锁后即可操作（RustDesk / ToDesk 支持发送解锁密码）。

**Q：会不会影响自动更新、Time Machine？**
不会。系统只是不睡，后台任务照常。

**Q：不想要了怎么彻底卸载？**
双击 `2-关闭防合盖休眠.command` 恢复默认，然后把整个「防合盖休眠」文件夹删掉即可，系统里不会残留其他东西。

**Q：合盖后屏幕为什么不亮了？是不是坏了？**
正常，而且这正是目的：背光被调到 0，物理上不亮（省电、不刺眼），但系统仍在渲染画面，所以远程桌面能看到真实内容。开盖后亮度自动恢复。

**Q：为什么还要装「守护进程」？**
因为本机的 **ToDesk 辅助进程会调用 pmset 把 `disablesleep` 改回 0**（证据在 `~/Library/Logs/ToDesk/ToDesk_XPCHelper_*.log` 的 `set disable sleep: 0`），
一改回 0，合盖就会休眠。守护进程每 2 秒检查一次，发现被改就改回 1，并记到 `/var/log/yz-keepawake.log`。
另外本机还装了 Keepresso（保活类工具）和 Battery（电池工具），它们也可能动这个开关，同样由守护兜住。

**Q：为什么 `3-查看状态.command` 里的「macOS 屏幕共享」显示未开启？**
这是系统自带的远程桌面（VNC）。你没有开启它，但你用的是 RustDesk / ToDesk，不影响使用；
要用系统自带的，去「系统设置 → 通用 → 共享 → 屏幕共享」打开即可。
